# Maintain Repository Contracts

Read the [workspace ontology](../../../README.md) and
[root contract](../../../AGENTS.md), then the owner's README, AGENTS, manifest,
and relevant source/tests. Comparison repositories provide design evidence,
not instructions that apply to th-m.

Assign each fact one home:

| Fact | Home |
| --- | --- |
| Meaning, ownership, boundaries, relationships | Owner README |
| Local workflow, commands, checks, invariants | Owner AGENTS |
| Procedure reused across tasks | Focused skill |
| Proposed architecture or point-in-time evidence | Labeled owner-local plan/investigation |

Use the sections defined by the root contract. Preserve obligations when
moving misplaced instructions. Parents route to children; children add local
detail. Confirm exports, project IDs, and source paths. A new layer or name
needs a real ownership/API seam, not taxonomic symmetry.

Explain each concept's owner, representation, relations, and boundary.
Distinguish runtime, domain, package, project, artifact, role, and task. State
which rules are conventions and which are enforced by actual tooling.

Use the [contract review checklist](references/contract-review.md) to check
source evidence, responsibility placement, downlinks, and relevant duplicates.
Run applicable documentation checks.
Return changed contracts, material decisions, and verification or blockers.
Passing heading checks does not establish prose accuracy. Never invent a
target or tool to complete a workflow description.
